# 听见之后

[打开产品 Demo](https://xxiaoqqq.github.io/waiting-mvp/)

听见之后帮助正在探索 AI 行业的人把长播客从“听过”变成“理解、联系、用起来”。它把真实音频、同步文字稿、章节、简短摘要、术语解释、跨节目观点和求职场景连接在一起；所有学习动作都可以跳过。

## 建议体验路径

1. 在「收听」点开一段文字或术语；用章节跳转，再手动回看并返回播放位置。
2. 在「知识库」按问题查看观点、不同节目的语境和原音出处。
3. 在「用起来 → 求职准备」点「看真实 AI 试跑案例」。看一条 JD 如何借用节目观点，也看一条没有依据的任务如何留空；点击出处回听，再返回求职卡片。
4. 自己粘贴 JD 时，公开版使用保守规则检索。节目观点是回答方法的参考，不能证明用户做过岗位工作。

## AI 在哪里发挥作用

私有 JD Agent 先由程序拆工作动作并检索已审定的知识候选，再让模型判断哪条观点可作为方法参考，最后由程序从知识原件填回出处并审查范围。公开案例展示的是**一次已保存的真实模型试跑结果**，不是每次点击都重新推理；普通访客不会触发私有模型费用。

在三份百度岗位的四句改写片段上，受控试跑保留了 12/12 条原句，找对 5/5 个事先标注的参考联系，未出现误连。三份样本参与过本地调试，不是独立盲测，也不足以证明任意完整 JD 可用。新节目仍需人工筛选、听音核对和审定观点后才能成为可靠的求职依据。

## 项目取舍

- Transcript 是收听主区域；解释和练习按需出现。
- 知识库保存可回听的观点、语境和边界，新增节目不会替换已有联系。
- JD 无合适节目依据时明确显示缺口；本人经历由用户自己补充。
- 在线模型调用有私有入口和额度上限；公开演示不开放无限调用。

这是一份可体验的 AI 产品案例，重点在真实用户摩擦、判断边界、失败后的修订及可核查的结果。代码与内容整理由 AI 协助完成，产品取舍来自用户持续测试和反馈。
